# 推送配置指南（国内 + 海外）

## 能不能直接用？

| 场景 | 能否收到提醒 |
|------|----------------|
| **零配置 + 用户开通知** | **能**（App 在后台、进程仍存活时，走 WebSocket + 本地通知） |
| **App 被系统完全杀掉** | **国内推荐 QQ 门铃**；海外可用 FCM。后端仍保留极光接口但 **App 已不再集成极光** |
| **零配置且未开通知** | **不能**（系统栏） |

类似 QQ 的分层：

1. **前台 / 回到首页**：WebSocket 实时；不在当前会话时，App 顶部展示 **应用内横幅**  
2. **后台但进程存活**：前台服务保 WebSocket + **系统栏本地通知**  
3. **进程被系统杀掉**：国内 **QQ 门铃**；海外 **FCM**（可选）  

---

## 架构简述

```
Tom 发消息 → Go 后端
              ├─ 任意设备 WebSocket 在线 → 仅 WS 下发（不发第三方推送 / QQ 门铃）
              └─ 用户完全离线
                    ├─ 已绑 QQ 且门铃开 → QQ 短文门铃
                    └─ 有 FCM token（海外包）→ FCM 密文推送
```

**安全模型**：FCM 与服务器之间传递的是 **消息密文** 及会话元数据，**不含明文**。系统栏明文在本机解密后由 `flutter_local_notifications` 展示。QQ 门铃仅发「有人发来消息」类短文，不含正文。

- 用户须在 **设置 → 通知** 中开启，并授予系统通知权限  
- **设置 → QQ 提醒**：绑定官方机器人作离线门铃 / 金句图 / 60s 资讯图  
- **前台服务保活**：维持 WebSocket；真机建议加入 **电池优化白名单**

## 一、后端（`deploy/.env`）

**仅测「后台长连接 + 本地通知」时可不配任何推送密钥。**

国内离线门铃见下文 **第四节 QQ 机器人**（`QQ_BOT_*`）。

### 海外（Firebase / FCM HTTP v1，可选）

Legacy **Server key** 已无法在新项目启用；请使用 **HTTP v1 + 服务账号**。

1. [Firebase Console](https://console.firebase.google.com/) 打开项目（如 **ihope-606b3**）
2. **项目设置 → 服务账号** → **生成新的私钥** → 下载 JSON  
3. 放到 `deploy/`（**勿提交 Git**），例如：`deploy/ihope-606b3-firebase-adminsdk-….json`
4. `google-services.json` 放到 **`mobile/android/app/src/global/`**（包名 **`com.clprince.ihope`**）
5. 写入 `deploy/.env`：

```env
FCM_CREDENTIALS_FILE=ihope-606b3-firebase-adminsdk-fbsvc-1db7523612.json
FCM_PROJECT_ID=ihope-606b3
FCM_CREDENTIALS_HOST_FILE=./ihope-606b3-firebase-adminsdk-fbsvc-1db7523612.json
```

Docker 生产会把 `FCM_CREDENTIALS_HOST_FILE` 挂进容器。亦可用整段 `FCM_CREDENTIALS_JSON`（优先于 FILE）。

### 极光（后端可选遗留）

后端仍可读 `JPUSH_APP_KEY` / `JPUSH_MASTER_SECRET`，但 **当前 Flutter 客户端已移除 jpush**，新用户不会再上报 `android_cn` token。日常国内请用 QQ 门铃，无需再配极光。

### GitHub 仓库 Secrets

| Secret 名称 | 用途 |
|-------------|------|
| `FCM_SERVICE_ACCOUNT_JSON` | 生产机 FCM v1（可选） |
| `API_BASE` / `ANDROID_KEYSTORE_*` | Release APK |

当前 CI 打 domestic APK **不需要** 极光 / FCM Secret。

## 二、Android 客户端

| Flavor | 包名 | 离线兜底 | 编译 define |
|--------|------|----------|-------------|
| `domestic` | `com.clprince.ihope.cn` | QQ 门铃（推荐） | `PUSH_CHANNEL=none` |
| `global` | `com.clprince.ihope` | FCM | `PUSH_CHANNEL=fcm` |

**后台本地通知**两个 flavor 均可用。

### 国内包

```powershell
cd D:\IHope\mobile
flutter pub get
flutter run --flavor domestic
# 或：--dart-define-from-file=config/domestic.json
```

### 海外包

```powershell
flutter run --flavor global --dart-define-from-file=config/global.json
```

需已放置 `android/app/src/global/google-services.json`。

### 未指定 flavor 时

必须带 `--flavor domestic` 或 `--flavor global`。

## 三、用户侧（真机）

1. 登录 App  
2. **设置 → 通知 → 开启「后台新消息通知」**  
3. 允许系统通知权限  
4. **国内机型**：建议允许 **自启动 / 后台运行 / 锁屏显示 / 电池白名单**  
5. 离线门铃：**设置 → QQ 提醒** 绑定机器人  

开启后：

- **在 App 内（如会话列表）**：新消息顶部应用内横幅  
- **切到后台**：常驻「正在接收新消息」+ 系统横幅  
- **划掉 App**：走 **QQ 门铃**（或海外 FCM）

## 四、QQ 机器人门铃与每日图卡（推荐作离线提醒）

不接厂商通道时，可用官方 QQ 机器人做「门铃」：用户完全离线时发文字提醒；并可每日推送**诗词图卡**与**每天60s读懂世界**资讯图。

### 后端 `deploy/.env`

```env
QQ_BOT_ENABLED=true
QQ_BOT_APP_ID=开放平台 AppID
QQ_BOT_APP_SECRET=开放平台 AppSecret
QQ_WEBHOOK_PATH=/api/webhooks/qq
QQ_POETRY_API_URL=https://v1.hitokoto.cn/?c=i
QQ_NEWS_60S_API_URL=https://60s.viki.moe/v2/60s?encoding=image-proxy
QQ_POETRY_FONT_PATH=D:\fonts\NotoSansSC-Regular.otf
QQ_DAILY_POETRY_HHMM=08:00
QQ_DAILY_NEWS_HHMM=08:05
QQ_DOORBELL_COOLDOWN_SEC=600
QQ_BOT_SYNC_MENU_PANEL=true
```

`APP_PUBLIC_URL` 须为 QQ 服务器可访问的公网地址（图卡上传回退会走 `GET /api/public/qq-media/{id}.png`）。  
`QQ_POETRY_FONT_PATH` 必须是可读的中文 TTF/OTF，否则金句图无法生成。

### 指令面板与底部菜单（OpenAPI）

QQ 官方支持在单聊展示 **底部自定义菜单** 与输入框 **「/」指令面板**，需通过 OpenAPI 配置（也可在开放平台「发布设置」里手工配）。  
文档：[自定义菜单与指令面板](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/menu-panel/)

| 能力 | 接口 | IHope 行为 |
|------|------|------------|
| 单聊底部菜单 | `PUT /v2/menu` | 帮助 / 诗词 / 金句 / 新闻 + 「开关」子菜单 |
| 单聊「/」指令 | `POST/PUT /v2/panels`（`scope=c2c`） | 全部文本指令（含开/关、解绑） |

`QQ_BOT_SYNC_MENU_PANEL=true`（默认）时，backend **启动且 token 校验成功** 后会自动同步上述配置；面板以 `remark=ihope-c2c-panel` 识别，重复启动会更新而非重复创建。  
写接口限频约 **10 QPM**，每个机器人最多 **20** 个面板；若同步失败请查看 `docker logs` 中 `qqbot: sync menu/panel failed`。

用户从面板点选指令后，QQ 会发 `C2C_MESSAGE_CREATE`（与手打「诗词」相同），由现有 `HandleInboundText` 处理。

### QQ 开放平台

1. [q.qq.com](https://q.qq.com/) 创建机器人，拿到 AppID / AppSecret  
2. 配置 IP 白名单与回调：`https://你的域名/api/webhooks/qq`（端口限 80/443/8080/8443）  
3. 沙箱自测 → 提审上线 → 用户在 QQ 中「添加使用」机器人  
4. 用户须允许机器人「主动消息」，否则门铃与每日推送会失败  

### App

**设置 → QQ 提醒** → 获取绑定码 → 在 QQ 把码发给机器人。

QQ 指令：`帮助` / `诗词` / `金句` / `新闻`（或 `60s`）/ `消息提醒开|关` / `诗词开|关` / `金句开|关` / `新闻开|关` / `解绑`。也可在单聊底部菜单或「/」面板点选（需 `QQ_BOT_SYNC_MENU_PANEL` 或开放平台手工配置）。

### 行为

| 场景 | 行为 |
|------|------|
| 用户有 WebSocket 在线 | 不发 QQ 门铃 |
| 用户离线且门铃开启 | 发「XX 发来一条消息…」（有冷却） |
| 每日定时 / QQ 指令「金句」 | 诗词 **PNG 图卡** |
| 每日定时 / QQ 指令「新闻」 | 60s 读世界 **原图** |

## 五、验证

### 长连接 + 本地通知（零第三方配置）

1. 后端可不设 `JPUSH_*` / `FCM_SERVER_KEY`  
2. Bob 登录并 **开启通知**  
3. Bob 留在 **会话列表（前台）** → Tom 发消息 → Bob 应看到 **应用内顶部横幅**  
4. Bob **按 Home 切到后台**（不要划掉 App）→ Tom 再发 → Bob 应看到 **系统横幅**  
5. 后端日志 **不应** 对该在线设备发 `[push]`（WS 在线则跳过）

### 离线兜底（QQ / FCM）

1. **国内**：配齐 `QQ_BOT_*`，用户绑定 QQ 门铃后划掉 App → 应收 QQ 短文  
2. **海外**：配齐 FCM + `global` flavor → 划掉 App 后应收系统横幅  

### QQ 门铃

1. 配齐 `QQ_BOT_*`，机器人回调可达，迁移已跑（`006_qq_bot.sql`）  
2. Bob 在 App **设置 → QQ 提醒** 绑定，并开启门铃  
3. Bob **完全离线**（划掉 App）→ Tom 发消息 → Bob QQ 收到门铃文字  
4. Bob 在线时再发 → 不应再发 QQ 门铃

## 六、常见问题

**Q：不配置极光/FCM 能收通知吗？**  
A：能。进程在后台且 WebSocket 连着时走本地通知。被杀掉后用 **QQ 门铃**（国内）或 FCM（海外）。

**Q：App 被杀掉还能推吗？**  
A：QQ 门铃可提醒有新消息；海外 FCM 可推系统通知。强制停止或关通知权限会影响系统栏，不影响 QQ 侧门铃（若已绑定且允许主动消息）。

**Q：国内能用 Firebase 吗？**  
A：不可靠。国内请用 **QQ 门铃**；海外包再用 FCM。

**Q：QQ 门铃会泄露消息内容吗？**  
A：不会。门铃只发「XX 发来一条消息」类短文，不含正文。

**Q：金句图空白/乱码？**  
A：检查 `QQ_POETRY_FONT_PATH` 是否指向可用中文字体。

**Q：还要配极光吗？**  
A：一般不必。客户端已移除 jpush；后端极光配置仅为遗留可选。

**Q：iOS？**  
A：无 Android 式前台服务；后台短暂存活时可走本地通知，长期离线依赖 APNs/FCM 或 QQ 门铃。

**Q：推送内容安全吗？**  
A：极光/FCM 链路只传 **密文**；通知栏明文由手机本地解密后展示。解密失败时显示类型占位（如 `[图片]`），不展示密文。

**Q：开放平台保存回调地址提示「校验失败」，但本机 curl 自测返回 signature？**  
A：说明 **签名算法没问题**，但 **QQ 平台服务器** 可能没收到正确响应。常见原因：

1. **Cloudflare 橙云拦截** — QQ 回调带 `User-Agent: QQBot-Callback`。在 CF 控制台加 **WAF 跳过规则**：URI Path 等于 `/api/webhooks/qq`，或暂时关闭 Bot Fight Mode 再点保存回调。  
2. **点保存时看 VPS 日志** — `docker logs -f ihope-backend | grep qqbot`。若无 `validation ok` 且 `ua=QQBot-Callback`，请求没到后端（CF/防火墙/SSL 模式问题）。若有该行但平台仍失败，核对开放平台 **AppSecret** 与 VPS `QQ_BOT_APP_SECRET` 是否完全一致。  
3. **SSL 模式** — 橙云 + 源站仅 HTTP :80 时，CF 须为 **Flexible** 或 **Full**（非 strict）；**Full (strict)** 须源站有有效 HTTPS 证书。  
4. **回调地址** — 必须是 `https://im.clprince.top/api/webhooks/qq`（与 `APP_PUBLIC_URL` + `QQ_WEBHOOK_PATH` 一致，无多余斜杠）。

**Q：内测 APK 从哪下载？**  
A：可在 [GitHub Releases](https://github.com/keller-cc/ihope/releases) 下载 CI 构建的 `app-domestic-release.apk`（见 [mobile/README.md](../mobile/README.md) 与 [开发指南 §10.3](./开发指南.md#103-github-actions-发布-apk)）；也可由服务器 `uploads/releases/latest.apk` 或 `APP_DOWNLOAD_URL` 分发。
